# Router 2.0 무자금 준비 작업

이 문서는 tBNB 충전 전에 완료할 1~6번 작업의 실행 기준이다. 어떤 명령도 지갑 서명이나 거래를 자동 실행하지 않는다.

| 번호 | 준비 결과 | 실행 시점/명령 |
|---|---|---|
| 1 | tLQC/WBNB V3 파일럿 수수료를 `2500`으로 고정 검사 | `npm run inspect:testnet-readiness` |
| 2 | LQC Flow, PancakeSwap V2, V3에 같은 입력량을 쓰는 견적 파일 생성 | 배포 후 `npm run prepare:route-probes`; 이어서 `EXECUTE_SMOKE_SWAP=false npm run smoke:testnet` |
| 3 | Execution/Native/Auto Router와 모든 등록 Adapter의 BNB·토큰 잔액, Router→Adapter 승인 잔량 검사 | `npm run monitor:testnet` |
| 4 | 체인 97, 최근 블록 180초, 설정 검증 실패·잔여 자산·잔여 승인을 Critical로 처리 | `MONITOR_MAX_BLOCK_AGE_SECONDS=180 npm run monitor:testnet` |
| 5 | 표준 JSON 입력, 컴파일러 설정, 생성자 인수를 포함한 BscScan 자료 생성 | 배포 후 `npm run prepare:verification` |
| 6 | 현재 UI 설정을 보존한 채 다음 설정과 복구 설정을 함께 생성 | 배포 후 `npm run prepare:router2-cutover` |

## 전환 순서

1. 전체 배포 완료 후 `validate:testnet`을 통과한다.
2. 읽기 전용 견적 비교와 `monitor:testnet`을 통과한다.
3. BscScan 검증 자료를 생성하고 주소·컴파일러·생성자 인수를 대조한다.
4. `prepare:router2-cutover`로 `next-config.js`, `rollback-config.js`, `manifest.json`을 만든다.
5. `next-config.js`를 적용한 뒤 UI 견적만 확인한다. 실패하면 즉시 `rollback-config.js`를 복원한다.
6. 실제 소액 거래는 별도 승인 후에만 수행한다.

## 현재 차단 항목

- 배포용 tBNB 부족
- 네 개 운영 역할 주소 미확정
- tLQC/WBNB PancakeSwap V3 수수료 2500 풀 미생성
- Router 2.0 실제 배포 기록 미생성

위 항목이 해결되기 전에는 기존 최소 Router UI 설정을 변경하지 않는다.

## tBNB 없이 추가 완료한 기반 작업

- Best Execution Proof를 실행 대상·호출 데이터·보낸 주소·value·nonce·deadline과 결합하는 실행 의도 증거
- 실행 의도와 실제 settlement 증거를 하나로 묶고 재생 및 거래 대체를 거부하는 검증기
- 60초 이하 유효기간과 요청 해시를 사용하는 다중 DEX 읽기 전용 견적 API/SDK 요청 규격
- 모바일 오류 유형별 최신 견적·네트워크 전환·재시도·tBNB 안내 복구 버튼
- 감사 패키지에 검증된 Proof 및 Settlement 개수와 증거 다이제스트를 결합하는 선택적 항목
- 원문 API 키를 저장하지 않는 해시 인증, 파트너별 호출 제한, 요청 추적 ID, 표준 오류를 갖춘 읽기 전용 견적 API 게이트웨이 기반
- 견적 제공자를 신뢰하지 않고 Proof 암호학 검증과 요청·Proof의 체인/토큰/수량/만료 일치를 서버에서 재검증하는 경계
- 같은 요청 ID의 동일 재시도는 같은 Proof로 응답하고, 다른 거래 내용으로 요청 ID를 재사용하면 차단하는 멱등성 보호
- 동시에 도착한 동일 요청은 하나의 견적 작업으로 합치고, 처리 중인 요청 ID에 다른 거래 내용을 끼워 넣으면 즉시 차단하는 동시성 보호
- 견적 제공자가 응답하지 않으면 제한 시간 후 표준 오류로 종료하고, 처리 중 요청 잠금을 해제해 안전한 재시도를 허용하는 복구 보호
- 서로 다른 동시 견적 작업 수를 제한하고 용량 초과 시 재시도 가능한 표준 오류로 차단하되, 동일 요청 재시도는 기존 작업에 안전하게 합류시키는 과부하 보호
- 만료 전 멱등성 기록을 임의 삭제하지 않는 완료 기록 상한과 만료 정리를 적용해 재시도 일관성과 메모리 보호를 함께 유지
- 고객 식별자·API 키·거래 내용을 노출하지 않고 정상·주의·과부하 상태와 처리 용량만 제공하는 읽기 전용 서비스 상태 기능
- 파트너가 연동 전에 지원 체인·요청/응답 버전·최대 유효시간·Proof·멱등성·상태 기능을 자동 확인하는 비민감 호환성 규격
- 파트너 클라이언트가 체인·규격 버전·견적 유효시간·필수 보안 기능의 누락이나 하향 변경을 연동 전에 차단하는 호환성 검사기
- `GET /v1/capabilities`, `GET /v1/health`, `POST /v1/quote`만 제공하고 메서드·JSON 유형·요청 크기를 제한하는 읽기 전용 HTTP 어댑터
- HTTP 경로·Bearer 인증·요청/응답 스키마·오류 상태를 고정하고 구현과의 불일치를 자동 검사하는 OpenAPI 3.1 파트너 규격
- HTTPS·응답 제한시간·호환성 선검사·상태 확인·Bearer 견적 요청·Proof 응답 검증을 제공하고 비밀키 노출을 차단하는 파트너 참조 클라이언트
- 네트워크·과부하 등 재시도 가능 오류에만 동일 요청 해시와 ID를 최대 2회 재사용하고, 재시도 전 만료를 다시 검사하는 제한형 복구 정책
- 파트너 클라이언트가 응답 헤더와 실제 JSON 바이트 크기를 모두 검사해 비정상 대용량 응답에 의한 메모리 고갈을 차단하는 응답 상한
- 견적·상태·오류를 포함한 모든 HTTP 응답에 `no-store`와 `nosniff`를 강제해 캐시 잔류와 콘텐츠 유형 오해석을 방지
- `Content-Length`와 실제 UTF-8 바이트 수를 대조하고 Transfer-Encoding 중복·압축 본문을 거부해 요청 밀수와 길이 위조를 차단
- 중복 고객 ID·중복 API 키 해시·비정상 고객 식별자를 시작 단계에서 거부해 인증과 호출 한도 정책의 모호성 및 우회를 방지
- API 키 목록에서 일치 항목을 조기에 반환하지 않고 모든 등록 해시를 상수시간 비교해 키의 등록 위치에 따른 인증 시간 정보 누출을 완화
- UI에 검증된 후보 수와 축약 Proof ID를 표시하고 Proof 생성·검증 실패 시 거래를 비활성화하는 방어
- 표시된 Proof의 거래쌍·수량·단일/분할 경로·각 분할 입력·최소 출력을 실행 직전에 다시 대조하는 결합 검증
- Proof 만료시간을 거래 deadline으로 사용하고 대상 컨트랙트·calldata·value·보낸 주소·nonce를 시뮬레이션과 지갑 요청 사이에 고정하는 실행 의도 검증
- 분할 경로 정상 갱신 250건과 경로·분할량·최소출력·거래쌍·만료·Proof 변조 250건을 반복하는 결정적 불변성 테스트

이 작업들은 지갑 서명, 온체인 배포, 테스트넷 주소 변경, 실제 Swap을 수행하지 않는다.
