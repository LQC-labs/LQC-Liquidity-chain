# LQC Flow DEX 외부감사 제출 체크리스트

이 문서는 독립 보안감사기관을 선정하고 동일한 검토 기준을 유지하기 위한 운영 체크리스트입니다.
이 문서 자체는 감사 완료나 보안 인증을 의미하지 않습니다.

## 기관 선정 기준

- [ ] Solidity DeFi와 BSC Router/AMM 감사 실적을 확인한다.
- [ ] 감사팀 구성원, 독립성, 과거 공개 보고서와 취약점 처리 방식을 확인한다.
- [ ] Router, Vault/Strategy, 권한·Timelock, Safe 연동, SDK 경계를 포함하는 범위를 서면으로 확정한다.
- [ ] 퍼징·불변성·수동 코드리뷰·권한 분석·재감사 포함 여부를 확인한다.
- [ ] 일정, 산출물, 수정 재검증 범위, 공개 보고서와 보고서 해시 제공 여부를 계약서에 명시한다.
- [ ] 감사기관에 개인키, 시드문구, `.env`, 실제 자금을 제공하지 않는다.

## 제출 기준 고정

- [ ] 감사 시작 직전 커밋 SHA를 고정하고 이동 중인 브랜치를 감사하지 않는다.
- [ ] `npm ci`, `npm run gate:stage1`, `npm run coverage:router-sdk` 결과를 저장한다.
- [ ] Node.js·Solidity·운영체제·컴파일러·optimizer·package-lock 해시를 기록한다.
- [ ] `AUDIT_HANDOFF.md`, `AUDIT_SCOPE.md`, `SECURITY_TEST_MATRIX.md`를 함께 제출한다.
- [ ] `audit/critical-surface.json`과 실제 ABI의 state-changing 함수 매핑을 확인한다.
- [ ] 배포 전에는 테스트넷 주소·Safe 정책·역할 분리·Allowlist·거래한도만 제출한다.

## 감사 중·수정·재감사

- [ ] 모든 질문과 답변을 커밋 SHA 또는 증거 파일과 연결한다.
- [ ] Critical/High 발견사항은 수정 전 메인넷 사용을 금지한다.
- [ ] 수정마다 회귀 테스트와 영향받은 권한·경제 불변식을 추가한다.
- [ ] 수정 커밋과 재현 명령을 감사기관에 전달한다.
- [ ] 최종 보고서가 실제 검토 커밋·범위·제외사항과 일치하는지 확인한다.
- [ ] 모든 Critical/High 항목에 감사기관의 재검증 상태를 기록한다.
- [ ] 보고서 URL과 SHA-256 해시를 보관하고, 감사 후 코드 변경은 별도 영향평가를 받는다.

## 메인넷 전제조건

- [ ] 독립감사 최종본과 Critical/High 수정 확인서가 있다.
- [ ] 제한된 테스트넷 운영과 긴급복구 훈련을 완료했다.
- [ ] Bug bounty 또는 공개 취약점 신고 절차를 준비했다.
- [ ] 법률·KYB·토큰·대출·브리지 범위는 별도 검토가 완료됐다.
- [ ] 위 조건 전에는 메인넷 배포, 실제 사용자 자금, 무제한 TVL을 활성화하지 않는다.
